# Task 03 synthetic driver validation demo

The configured checklist is synthetic: `demo_identity_document` (no expiration), `demo_vehicle_document` (expiration required), and `demo_expiring_credential` (expiration required). These names and labels exercise a workflow and make no legal or compliance claim. Upload only known-safe synthetic PDF/JPEG/PNG files. Real personal-document intake remains blocked until Product Scope Q3, a malware scanning/quarantine policy, and Q7 retention/access/deletion procedures are decided.

Each upload is at most 10 MiB. Extension, declared MIME, signature and parser must agree. Images are limited to 8000 pixels per dimension and 24 million pixels total. A PostgreSQL `AuthThrottle` row limits each authenticated driver/source pair to 20 upload attempts per hour, including failed file validations; it does not delete version history. These parser checks are not malware detection, and the server cannot verify that a valid-looking file is synthetic; restrict this demo environment and do not accept real documents. At the proxy, cap multipart request bodies slightly above 10 MiB to account for headers and fields. Never expose the private volume through a web alias.

Bytes are stored under `PRIVATE_UPLOAD_ROOT` on the Compose `private_uploads` volume, outside static/media roots. Database rows and private files are one backup and restore unit. Task 09 owns the restore rehearsal. Reviewed versions and historical decisions remain retained in this synthetic MVP while Q7 is unresolved. Application audit rows are append-only through the exposed API, but database operators can change them.

Host browser smoke: use the established same-origin HTTPS setup and synthetic accounts. Register/login a driver, fill profile basics, upload three generated demo files, submit, then login as an administrator. Open the pending detail, download each exact revision file and check `AdminActionLog` has three `document_read` rows. Reject with observations; as the driver, verify history, replace one document, resubmit, then approve as admin. From a second driver and a parent session, direct GETs to each document ID must fail. A stale admin detail for a superseded pending revision must return `409 stale_validation` on approval. Check downloads have attachment, no-store and nosniff headers and that no `/static/` or `/media/` URL serves the file.
