## Convenciones y cobertura

Una fila representa una pantalla efectiva, una subvista con propósito propio o un subflujo que no puede perderse durante la migración. Los formularios/confirmaciones también se inventarían aunque no tengan URL. No se crean rutas nuevas para llenar el inventario. Un grupo de etapas conserva cada etapa nombrada y requiere evidencia de cada una.

Todas las filas fueron **inspeccionadas desde código** y quedan **pendientes de observación visual actual**. Los hallazgos H se refieren a la auditoría. «Conservar» significa que no se encontró motivo concreto para rediseñar ese comportamiento; sigue sujeto a revisión transversal. Heredar H01/H02/H08 señala que consume reglas compartidas en deriva, no que exista un recorte visual observado en esa pantalla.

Prioridades: **P0** = conservación/seguridad/recuperación y verificación obligatorias en el corte; no implica reescritura. **P1** = mejora candidata antes de la feria según capacidad/aprobación. **P2** = mejora posterior; comprobar que siga funcionando si recibe cambios compartidos. Ninguna fila P2 se elimina del alcance global. Una fila sin cambio específico recibe tokens/componentes comunes solo después de comprobar su efecto.

Aceptación base **A0**, aplicable a cada fila: datos y permisos correctos; carga/error/vacío pertinentes; nombres/textos largos; acciones y estado comprensibles; foco/regreso; sin doble envío ni datos de otra identidad; sin recorte esencial en tamaños/escala definidos; evidencia visual actual revisada. Los criterios de cada fila se suman a A0. Estados S01–S12 amplían esta cobertura a todos los consumidores aplicables.
