## Dependencias y criterio de avance

Cada lote revisa primero los componentes y datos reales del checkout, después adopta las primitivas que correspondan. Conservar las correcciones T12 previas; no reabrir automáticamente problemas ya resueltos de la auditoría. UX03 (identidad de soporte) y cualquier asociación ausente en reportes necesitan autorización de contratos/backend por separado y no son condición para aplicar lenguaje visual con los datos disponibles.

Salida de cada lote: cambios acotados, pruebas de estados/permisos/sesión pertinentes, build/análisis/lint/contratos aplicables, instrucciones o capturas sin datos privados y revisión humana. No acumular cambios del lote siguiente mientras se espera esa revisión. El lote 1 se detiene antes de modificar cualquiera de las filas propuestas.
